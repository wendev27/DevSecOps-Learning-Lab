# Cybersecurity Concepts

## Overview

This directory is for foundational explanations that make cybersecurity topics easier to understand and apply. It should answer questions such as what a control does, which risk it addresses, what assumptions it relies on, and where it can fail.

The concepts here support the broader [Cybersecurity Mastery](../README.md) learning workflow. They are independent study notes and do not replace the documentation of a system under review.

## Learning domains

Concept notes may cover:

1. Security Governance, Risk, and Compliance
2. Identity and Access Management
3. Network Security
4. Endpoint Security
5. Cloud Security
6. Security Operations and Incident Response
7. Vulnerability Management
8. Application and API Security
9. Data Protection and Privacy
10. Security Architecture and Engineering

These are learning topics, not claims that every domain has already been studied or documented. The current directory contains this guide only; topic notes should be added when they provide useful, independently written understanding.

## How to use this directory

1. Choose a concept connected to the current learning goal.
2. Explain the terms, relationships, risks, and defensive controls in your own words.
3. Note assumptions, trade-offs, and examples that can be tested safely.
4. Use [`review/`](../review/README.md) to condense the material into revision prompts or checklists.
5. Use [`practice/`](../practice/README.md) to test whether the concept can be applied.
6. Record difficult or unresolved areas in [`progress/`](../progress/README.md).

## Suggested note format

A useful concept note can include:

- Definition and context.
- Security objective or risk addressed.
- Relevant controls, technologies, or processes.
- A small authorized example.
- Common misconceptions and limitations.
- Related topics and questions for further study.
- Status: `Planned`, `In progress`, `Completed`, or `Needs review`.

Do not label a concept completed simply because a definition was read. Completion should reflect an explanation that can be revisited and, where appropriate, applied in practice.
