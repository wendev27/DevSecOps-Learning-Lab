# 📈 Monitoring & Observability

Welcome to the Monitoring & Observability labs.

This section focuses on understanding how modern systems are monitored, how application health is measured, and how engineers detect problems before users are affected.

Monitoring answers:

> "What is happening right now?"

Observability answers:

> "Why is it happening?"

As applications grow into multiple services, logs alone are no longer enough. Metrics, dashboards, health checks, and alerts become essential tools for maintaining reliability and performance.

# 🧠 Core Concepts

## Monitoring

Monitoring tracks the health and performance of systems by collecting data such as:

- CPU usage
- Memory usage
- Request count
- Response time
- Error rate
- Uptime

Its main purpose is to answer:

> "Is the system healthy?"

---

## Observability

Observability goes beyond monitoring.

It helps engineers investigate:

- Why an error happened
- Which service failed
- Where latency originated
- How components interact

The three pillars of observability are:

### 📊 Metrics

Numerical measurements collected over time.

Examples:

- Requests per second
- CPU utilization
- Memory consumption
- Error rates

---

### 📝 Logs

Records of events generated by applications and infrastructure.

Examples:

- User login attempts
- API requests
- Database errors
- System warnings

---

### 🔍 Traces

Track a request as it moves across multiple services.

Useful for understanding:

- Bottlenecks
- Latency
- Service dependencies

# 🚀 Why This Matters

A working application is not enough.

Production systems require engineers to answer questions like:

- Is the application healthy?
- How many requests are failing?
- Why is performance degrading?
- Which service caused the outage?
- How can problems be detected early?

Monitoring and observability provide the visibility needed to operate systems reliably at scale.
